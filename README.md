# bus_colinear
🚇 公交与轨道共线智能分析系统 (V2.2)
本系统是一款专为交通规划、调研设计的轻量化 Web 工具，旨在快速分析北京地铁线路（既有及规划）与周边公交线路的共线重叠情况，并提供直观的可视化图表。 

1. 核心搭建思路与逻辑
系统采用 Streamlit 作为前端框架，后台接入 高德地图 Web 服务 API。其核心逻辑架构如下： 


数据层：内置北京 1-20 号线完整地铁站点数据库（2026.03 版），并支持用户手动输入坐标。 

处理层：

坐标转换：将输入的站名通过地理编码转换为高德经纬度坐标（规划模式则直接跳过此步）。

周边搜索：基于 500 米半径（默认）搜索站点周边的公交站点及线路。

共线算法：通过逻辑运算提取在不同轨道站点之间重复出现的公交线路，识别其共线区段。

展示层：利用 Matplotlib 绘制类似甘特图的共线段分布图，并支持结构化数据 CSV 导出。

2. 三大平行功能块
根据调研场景的不同，系统设计了三个平行的功能入口： 

🟢 既有全线分析 (下拉模式)

适用场景：对北京现有的完整地铁线路进行宏观评估。 


实现逻辑：从下拉菜单中直接选择线路（如 13 号线），系统自动调取该线路所有站点序列进行一键分析。 

🟡 既有区间 (手动模式)

适用场景：跨线调研、特定区段测试或临时增减站点的场景。 


实现逻辑：支持手动输入站点名称列表，灵活性极高。 

⚫ 规划线路 (坐标模式)

适用场景：针对尚未建成的规划线路，在没有标准站名的情况下，通过人工拾取的精确坐标进行模拟分析。 


实现逻辑：直接输入“名称+经纬度”序列，系统绕过站名解析，精准搜索对应坐标点的公交接驳。 

3. 使用方法与规范
为了确保系统能准确解析您的意图，请遵循以下输入规范：

⌨️ 输入规范说明
英文标点：所有逗号 ,、分号 ; 以及坐标里的逗号必须使用英文半角输入法。

间隔规则：

区间模式：站点之间使用英文逗号 , 隔开。


坐标模式：站名与坐标之间必须有一个空格，不同站点之间使用英文分号 ; 结束。 

🚀 操作步骤
模式选择：在左侧侧边栏根据需求选择对应的调研模式。

数据录入：

若是“规划线路”，可点击侧边栏链接前往  获取点位。 

按照示例格式：点位A 116.27,40.03; 点位B 116.30,40.04; 进行输入。

配置密钥：输入您的高德 API Key（若后台已配置 Secrets 可忽略）。

执行分析：点击“启动核心分析”，等待进度条完成。

结果导出：查看可视化图表后，点击下方的“导出分析明细 (CSV)”保存原始数据。
